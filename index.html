このアプリについて

集合住宅システムにつながる外部装置（宅配ボックス・非接触キー・エレベータ・警報発信装置など）をパソコンで疑似し、実機を用意せずに通信試験を行うためのツールです。相手装置になりすまして電文を送り、受け取った電文が通信仕様どおりかを桁ごとに検証します。

  • アイホンの通信仕様書6冊と、パナソニックの5冊に対応しています
  • 送る前に必ずプレビューで電文を確認できます
  • 受信した電文は「どの桁が何を意味するか」まで分解して表示します
  • 仕様に合わない値は黙って直さず、理由を示して止めます

最初にすること

  1. COMポートを選ぶ（画面上部）。一覧に出ないときは↻で更新します
  2. 通信プリセットを選ぶ。対象装置に合う条件（宅配／MCなら4800,E,8,1など）を選びます
  3. 接続を押します
  4. 左のメニューから対象の装置を選びます
  5. 値を入れて検証・プレビューで電文を確認し、送信します
  6. 右側の通信ログで送受信と解析結果を確認します

接続したまま別の画面へ移ると、装置ごとに通信条件が違うため上部に警告が出ます。その場合はいったん切断し、プリセットを選び直してから接続してください。

汎用ターミナル

任意のバイト列を送るための画面です。仕様が分からない電文の調査や、専用画面にない電文を送るときに使います。

  • HEX（例 02 31 03）かASCIIで入力します
  • STX／ETXの付加、BCC（XOR・加算）の自動計算ができます
  • 「BCCを故意に破壊」で異常電文を作れます
  • 下のボタンからENQ・ACK・NAK・EOTなどの制御コードを単独で送れます

宅配 4線式(B方式)　Q48-005F

宅配ボックスと集合住宅システムのあいだの通信です。100件のロッカー表を編集して送ります。

  • 動作で、自分が宅配ボックス側（情報応答）かシステム側（情報要求）かを選びます
  • ロッカー表で棟番号・住戸番号・状態を設定します。範囲指定の一括設定が使えます
  • 送信したい行のチェックを入れてから送信します
  • 1パケットの件数（3件／10件）を超える分は自動で複数パケットに分かれ、パッケージNOで残数を示します
  • 対象プロファイルでシステム／基板／2方向アダプター段数を選ぶと、最大ロッカー数・最大ロッカーNo・パケットNo・状態コードを仕様上限で検査します
  • 宅配側で動作しているとき、情報要求を受けたら現在のロッカー表で自動応答できます

宅配 2線式　Q55-001D

宅配ボックスからの一方向通信です。応答は返りません。

  • 住戸アドレスは「登録順の連番」という規定どおり自動採番されるため、入力しません
  • 対象システム（標準／PATMOα）でボックス数の上限が変わります
  • 登録した行は5件ずつ、1秒間隔で送信されます
  • 受信モニタの下に「住戸別の受信状況」があり、相手が全ロッカーを連続送信しても住戸単位で最新状態を追えます

非接触キー　Q48-006F

キーをかざした情報を送ります。10byte（個人番号なし）と13byte（個人番号あり）の2形式があります。

  • 対象システムを選ぶと、棟番号・個人番号の上限が変わります（V-fineは個人番号8まで、など）
  • 上限を超える値は「注意」として表示し、電文は仕様どおりに作ります
  • 受信側として動作するときは、BCCが正しければACK、異常ならNAKを自動で返せます

マンション制御　Q48-008I

マンションコントローラと集合インターホンのあいだの通信です。110種類のコマンドを扱います。

  • Version（1〜3）と動作側（MC／IC）で、選べるコマンドが変わります
  • VIXUS Advanceでは、静止画機能を全静止画消去（45H／65H）と全住戸情報初期化（54H／74H）に限定します
  • 「起動・周期通信開始」は、起動時の初期化電文を10秒間隔で再送し、通信接続開始後は30秒ごとにヘルスチェックを送受信します
  • 初期化・警報出力・宅配ボックス制御・非接触キー制御は、項目を入力すると仕様どおりのメッセージを組み立てます
  • それ以外のコマンドは「仕様定義でメッセージを組み立てる」のチェックを外し、MESGを直接入力します
  • ADDR（住戸アドレス）は棟コード2桁＋装置番号4桁です。棟なしはBB、1〜9棟はB1〜B9になります

エレベータ連動（アイホン）　Q46-005J

21byte固定、全13コマンドです。機種プロファイルで使えるコマンドが変わります。

  • 対象で機種（DASH VHX、V-fine VBZ、VIXUSなど）を選ぶと、その機種で使えないコマンドは弾かれます
  • 送信元で優先局が決まります。ENQ衝突時は集合インターホン側が優先します
  • EV側で動作しているとき、ECALLを受けたらかご状態に応じてESTAT／ESTOPで自動応答できます

エレベータ連動（パナソニック）

18byte固定、全5コマンド（IE／IK／IH／SB／SH）です。アイホンとは通信手順が違います。

  • 正常応答が10H／30Hの2種類で、NAKがありません。検証できない電文には応答せず、相手の再送を待ちます
  • 共同玄関解錠(IK)は付加コードで種類が変わり、住戸を特定できるのは00（住戸による解錠）だけです。01（管理室）・02（暗証番号）では棟番号・住戸番号が固定値のため入力できません
  • ENQ衝突時は送信権を相手へ渡し、エレベータ1秒・IFU2秒と待ち時間に差をつけて再送します
  • ヘルスチェック(IH)を受けたら、運行状態（正常運行中／点検中）を載せた応答(SH)を自動で返せます
  • IFU側では1分周期のヘルスチェックを有効にでき、送信完了後1秒以内のENQ受信を通信正常として判定します

警報（アイホン）　Q49-023G

11byte固定。発信情報のビットに警報が割り付けられています。

  • ビット割付（標準／パターン1〜3）を選ぶと、各ビットの意味が変わります。画面には警報名が出ます
  • ◇が付くビットは対応付けを変更できない項目、空欄は未割付です。未使用ビットはチェックできません
  • ヒストリー要求を受けたら、記録した履歴を古い順に返せます（最大15件、リング状）
  • 発報元は住戸のほか、管理室・集合玄関・共用部を選べます

警報（パナソニック）

1つの画面で4プロトコル（HPC／TSS／大興／リモート）を切り替えます。形式が2種類あります。

  • 上部の通信プリセットはメーカー別ではなく、STX形式（アイホン／HPC／TSS）とASCII形式（大興／リモート）に分かれています
  • HPC／TSS … STXで始まる11byte固定。1200,E,8,1
  • 大興／リモート … SNDで始まるASCIIレコード（最大10件）。1200,N,8,1。パリティを使いません
  • プロトコルを切り替えると、電文形式・通信条件・入力欄・受信の読み方がまとめて変わります
  • HPCは現状＋過去15件を保持し、過去情報なし・住戸記録なし・2棟以上の住戸要求にはNAKを返します
  • TSSはENQのACK以外5回／無応答256回、テキストのNAK／無応答5回を別々に数えて再送します
  • リモートの定時送信は受信装置→IFUです。IFUは定時アンサーバック後10秒まで警報送信を保留し、DTR／RTSもタイミングチャートに沿って制御できます
  • 受信した電文からプロトコルを判定します。一意に決まれば自動で切り替え、決められないときは候補と「どちらで読むと何になるか」を示します（詳しくは「困ったときは」）

電文変換（ブリッジ）

受信した電文を別の形式へ読み替えて送信します。受信ポートと送信ポートに別のCOMポートを使います。

画面上部の接続が受信ポート、この画面の「回線」で開くのが送信ポートです。RS422とRS232Cのように電気規格が違っても、それぞれの変換器を挿せばどちらもCOMポートとして扱えます。

警報（メーカー間）

  • アイホン Q49-023G ⇄ パナソニック4種を双方向に変換します
  • この対応付けは通信仕様書には規定がありません。両仕様書の警報名が一致することだけを根拠にした変換です
  • 相手に枠がない警報（HPCの「水漏れ」「CO」など）は送れないため、理由を表示します
  • 変換表を画面で確認できます

宅配・非接触キー → マンションコントローラ

  • こちらは Q48-008I 側に受け皿（6.7 宅配ボックス制御／6.8 非接触キー制御）があるため、仕様の定義に沿った変換です
  • 非接触キーはゲート番号・住戸・個人番号がそのまま載ります
  • 宅配4線式は「荷物なし→取出し状態」「荷物あり→着荷状態」だけが対応します。集荷預り・食配着荷・書留着荷・宅配ロボには対応する状態がないため送れません
  • 装置からMCへの一方向です。MCから装置へ状態を書き込む電文は仕様上ありません

実際の集合インターホンのように宅配ボックスと非接触キーを同時に中継できます。「2台目の装置も同時に中継する」を有効にすると、受信ポート1で選ばなかったほうの装置を受信ポート2で受けます。回線は受信2つ＋送信1つの計3つで、通信条件は装置ごと（宅配4800,E,8,1／非接触キー9600,E,8,1／MC 4800,E,8,1）に開きます。同じCOMポートを複数の回線には使えません。

異常注入

わざと異常な通信を起こして、相手装置の動きを確かめます。

  • BCC異常・BCC欠落・送信遅延・無送信・STX重複を選べます
  • 対象段階で、ENQだけ・電文だけ・応答だけ、と適用先を絞れます
  • 適用回で、毎回か1回目だけかを選べます
  • プレビューには正常な電文、ログには実際に送った値が残ります
  • 受信時の自動応答（ACK／NAK／無応答）もここで切り替えます

通信設定

  • ボーレート・パリティなどを個別に指定できます（プリセットで足りないとき）
  • DTR／RTSの操作と、CTS／DSR／DCDの取得ができます
  • 通信条件の判別で、相手の条件が分からないときに順に試して探せます。ENQで始まる機器にはACKを返して本文まで取得します
  • 全画面の入力値をこのPCへ保存したり、設定JSONとして共有できます
  • 試験結果JSONにはバージョン、通信条件、設定、通信ログ、受信モニタ履歴がまとめて入ります
  • 通信ログの保持件数（2,000／20,000／100,000件）を選べます。画面には最新2,000件だけを描画し、保存時は保持中の全件を出力します

困ったときは

相手の通信速度やパリティが分からない

「通信設定」画面の通信条件の判別を使います。条件を順に切り替えて実際に受信し、仕様どおりのフレームとして読める設定を探します。見つかった条件はボタン1つで反映できます。

判別中は接続を切ります。相手が自発的に送信している状態（警報を発生させる、キーをかざす、など）にしてから実行してください。警報STX方式などは、ENQ受信時に試験用ACKを返して本文を取得します。

受信データが化けている

受信モニタが偏りから当たりを付けます。「1バイトあたりのビット変化が少なく00Hが多い」なら設定が相手より速い、「ビット変化が多いのに電文より短い」なら遅い可能性があります。目安のボーレートも示しますが、確定するには上記の判別を実行してください。

どのプロトコルの電文か分からない（警報）

警報（パナソニック）画面の受信モニタが、アイホンQ49-023Gとパナソニック4種のどれとして成立するかを判定します。プロトコル固有の要素があれば一意に特定し、共通部分しかない電文では候補と読みの違いを示します。

  • 発報元が管理室・集合玄関・共用部 → アイホン
  • 発信種別 05H・10H → HPC ／ 44H → TSSまたはアイホン
  • 警報No.40（宅配登録･削除）や定時送信 → リモート
  • 発信種別 00H・01H だけの電文は、アイホン／HPC／TSSのどれでも成立するため決められません

送ったのに応答がない

  • 通信条件（特にパリティ）が合っているか。上部の警告と「通信条件の判別」で確認します
  • 動作側（自分がどちら側か）の設定が相手と噛み合っているか
  • 送信方式が「電文のみ」になっていないか。仕様手順にするとENQから始めます
  • 異常注入が「無送信」や「無応答」のまま残っていないか

試験の記録を残したい

通信ログの↓ボタンでテキスト保存できます。再現に必要な情報をまとめる場合は、通信ログ上部のJSONまたは通信設定画面の試験結果JSONを書き出しを使ってください。バージョン・通信条件・全画面の設定・ログ・受信モニタ履歴が1ファイルに入ります。
